The problem we had

Our reporting grew report by report, team by team. Across the organisation there were 10 Power BI workspaces with 35 reports. Many indicators existed in several places, built in slightly different ways.

Simple questions took days and depended on who you asked:

  • Where does this number come from: the outage management system, asset data, or a spreadsheet?
  • Which report should I use, and which version is the official one?
  • When was it last updated, and who owns it?
  • Why do two reports show different values for "the same" indicator?

For a new staff member there was no starting point except asking colleagues. Knowledge lived in people's heads and in copies of files that went out of date.

What the Indicator Library is

An always-current reference of our reporting, built automatically from Power BI itself. It comes in two editions for two audiences.

For all staff: the Viewer

Search an indicator and see, in plain language, what it means, where its data comes from (outage system, asset data, surveys, files), which reports show it, who owns it, and when it was last refreshed. No technical detail.

For the BI team: the full catalog

The same information plus the technical detail: the calculations, the source tables, refresh health, duplicates and a list of issues to fix. Two views: one starting from reports, one starting from data models.

A tool to improve, not only describe

The library also lets the BI team apply naming, folder and documentation standards across many models at once, with owner approval and a full undo history.

How it works, in plain terms

Think of it as a library catalogue that writes itself. It reads the "recipe" of each report, not the data in it.

  • Effort to refresh: one double-click by a BI analyst; 30 minutes to 2 hours for everything, much less for a few workspaces.
  • No new platform: it uses Microsoft's own Power BI and Fabric interfaces with the analyst's existing access. No new database, licence or server software.
  • Changes are controlled: nothing is changed in a live report unless an owner has approved it and an analyst sends that one report deliberately. Every change is recorded and can be undone.

Privacy and safety

The library never reads customer or record-level data. It only reads how reports are built: names, calculations, data sources and refresh times.

  • Anything that looks like a password or a customer identifier inside report code is hidden before the catalog is built.
  • The all-staff edition is built separately, with all technical detail removed. An automatic check stops the build if server or table names get into it.
  • The detailed edition stays inside the BI team.
  • Planned hosting uses Windows sign-in, with access granted by AD group, so access can be given and removed centrally.

What we need from leaders

  1. Support the hosting request to IT. A small internal website: static files, no new platform, an estimated hour of IT work. Two access groups: all staff (plain edition) and the BI team (detailed edition).
  2. Name indicator owners and ask them to approve descriptions and business definitions for their indicators, with a target date.
  3. Agree one official definition for each externally reported indicator (reliability indices, restoration time, repeat outages, call times, planned outages), starting with the most repeated.
  4. Set the refresh cadence (weekly, monthly or quarterly) and who is accountable for running it.
  5. Endorse the model standards once drafted, so new reports follow them from the start.

How we will know it is working (review after 3 months)

  • Number of staff using the library
  • Indicators with an approved business definition
  • Duplicate or redundant reports retired
  • Fewer "which report has X?" requests to the BI team

How a new staff member uses it

  1. Open the library and search for the indicator, for example "customer hours interrupted" or "call resolution time".
  2. Read the definition: what it measures, numerator and denominator, and who owns it.
  3. See where it comes from: the outage management system, asset data, a survey or a file, and when it was last refreshed.
  4. Open the right report from the link, knowing it is the official one.
  5. For analysts: before building anything new, check whether the indicator already exists and reuse the certified version.
